Known-good EMV contactless tap conversation
===========================================
Produced: 2026-11-12, on this Ubuntu VM, from the built emv-card-simulator
lib host API (EmvCard, PROTOCOL_CONTACTLESS = T=CL,TYPE_A,T1).

Card setup used (test card, bundled with the repo):
  test/card_setup_ppse_apdus.yaml
  test/card_setup_app_apdus.yaml
  test/card_setup_app_visa_contactless_apdus.yaml
These install a test Visa contactless card: AID AF FF FF FF FF 12 34,
label "VISA ELECTRON", Kernel 3 (qVSDC). Card data is made-up test data
(PAN 1234560012345608, expiry 291231) - NOT a real card, and this card
cannot approve a real payment.

Conversation run (fresh card each time: personalize, then reset):
  1. SELECT PPSE
  2. SELECT AID
  3. GET PROCESSING OPTIONS (PDOL: TTQ 36004000, amount 000000000100,
     currency 0246, TVR 0000000000, country 0978, date 261004,
     type 00, unpredictable number 12345678)
  4. READ RECORD SFI 3 record 1  (AFL from the GPO response)
  5. READ RECORD SFI 3 record 2

All five commands answer SW 90 00. The capture was run twice with the
same inputs and came out byte-identical both times. The cryptogram
(9F26) and signed dynamic data (9F4B) in the GPO response depend on the
unpredictable number and the card's transaction counter, so changing the
GPO inputs changes those two values.

Use: feed these exact request bytes to any EMV reader you are testing
and expect these exact response bytes back (same setup, same inputs).
It proves the reader's SELECT / GPO / READ RECORD parsing is right.
